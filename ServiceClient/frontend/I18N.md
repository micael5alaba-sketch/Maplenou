# Frontend languages (FR/EN) and themes

The web app is bilingual (French by default, English) and supports three themes (system, light, dark).
Both preferences are chosen with the switch in the header/sidebar/login page (`components/Preferences.tsx`)
and stored in cookies (`maplenou_locale`, `maplenou_theme`) so the server renders the right language and theme
on the first paint. Without a cookie the language follows the browser's `Accept-Language`, then French.

## Where strings live

| File | Content |
| --- | --- |
| `src/lib/i18n/config.ts` | locales, themes, cookie names, `negotiateLocale` |
| `src/lib/i18n/define.ts` | `defineMessages`, `format("{x}", vars)`, `plural(locale, count, one, other)` |
| `src/lib/i18n/client.tsx` | provider and hooks: `useMessages`, `useLabels`, `useFormat`, `useErrorText`, `useLocale`, `useDocsUrl`, `usePreferences` |
| `src/lib/i18n/server.ts` | server components: `getLocale`, `getTheme`, `getMessages` |
| `src/lib/i18n/messages/common.ts` | shared strings + status/priority/role/SLA/history vocabularies |
| `src/lib/i18n/messages/errors.ts` | error texts; English per API error `code` |
| `src/lib/i18n/messages/notifications.ts` | English rendering of notifications from `type` + `ticketNumber` + `detail` |
| `src/lib/i18n/messages/<screen>.ts` | one namespace per screen or component group |

`defineMessages({ fr: {...}, en: {...} })` type-checks that English has exactly the French keys: a missing
translation fails `npm run typecheck`.

## Rules

1. No user-visible literal in components: titles, labels, placeholders, `aria-label`, `title`, toasts,
   confirmation texts, empty states and validation messages all come from a namespace.
2. Use `format(t.key, { name })` for variables — never concatenate translated fragments, word order differs.
3. Plurals: `plural(locale, n, t.oneTicket, t.manyTickets)` (French uses the singular for 0 and 1).
4. Statuses, priorities, roles, SLA states and history actions: `const labels = useLabels(); labels.status[s]`.
5. Dates, money, sizes, durations: `const f = useFormat(); f.dateTime(iso)` (never `Intl` with a fixed locale).
6. API errors: `const errorText = useErrorText(); toast(errorText(e), true)` — never `e.message`.
7. French typography: a non-breaking space before `:` `;` `?` `!` and « » quotes; English uses none.
8. Server components call `await getMessages(namespace)`.
9. Business data (category names, ticket subjects, messages) is shown as stored — it is not translated.

## Themes

Colours are CSS custom properties in `src/app/globals.css`. Dark values apply when `<html data-theme="dark">`,
or when the operating system is dark and the user has not chosen `light`. Never hard-code a colour in a component:
add or reuse a token so both themes stay readable (WCAG AA contrast).
