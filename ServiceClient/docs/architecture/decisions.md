# CS-03 Architecture and Implementation Decisions

**Status:** PROPOSED — implemented, awaiting project-owner approval.
These decisions close the technology questions CS-02 left open ("stack choice remains subject to CS-03
technical planning") and record every place where the implementation had to interpret an approved rule.
Business rules DEC-001…DEC-007 are unchanged.

| ID | Decision | Rationale / source |
| --- | --- | --- |
| DEC-CS03-01 | **Stack:** Spring Boot 4.1 (Java 21) REST API, PostgreSQL 16 with Flyway migrations, Next.js 16 (React 19, TypeScript) web app. Flutter apps consume the same API. | Named in the functional design (§13), the roadmap and the architecture mockup. Java 21 is the current LTS available on the build machines. |
| DEC-CS03-02 | **Authentication:** the API is an OAuth2 resource server validating JWT bearer tokens (`sub` = user id, `roles` claim). In production tokens come from the Maplenou identity provider (`issuer-uri`). HS256 tokens issued by the module itself exist only in the `demo` profile and tests. | BR-004 (identity from the token), BR-073. The identity provider is not yet specified, so the module does not own passwords. |
| DEC-CS03-03 | *(amended 2026-10-29 by DEC-CS10-17: support roles of Maplenou accounts are given by phone number in `support_staff_assignments`)* **User projection:** the module keeps `support_users` (id, name, contact, role, active) refreshed from tokens. Administrators can deactivate a support account locally; roles stay managed by the identity provider. | Needed for assignment (BR-013), display names and history; avoids coupling to an undefined user service. |
| DEC-CS03-04 | **Ticket number:** `TKT-<year>-<sequence>` (5 digits minimum) from one PostgreSQL sequence that never resets or reuses values. | BR-002; format shown in the functional design and mockups. |
| DEC-CS03-05 | *(superseded on 2026-10-29 by DEC-CS10-16: SLA counted 24/7 by default; this business-hours calendar remains available as `SLA_MODE=business-hours`)* **Business calendar:** time zone Africa/Lomé; Monday–Friday 08:00–18:00; holidays maintained by administrators in `business_holidays` (not pre-filled — the official calendar must be loaded). **One business day = 10 business hours** for the resolution targets expressed in days. | DEC-001 / BR-032. The day/hour conversion is an interpretation: **owner confirmation needed.** |
| DEC-CS03-06 | **SLA clock:** not paused while `WAITING_FOR_CUSTOMER`; "approaching" = 75 % of the target elapsed; overall state = worst of first-response and resolution. First response = first customer-visible message from support staff. | CS-02 SLA states. Pausing during customer wait was not approved, so it is not applied — candidate upgrade. |
| DEC-CS03-07 | **Lifecycle details:** `NEW → ASSIGNED` only by assignment; `ASSIGNED → IN_PROGRESS / WAITING_FOR_CUSTOMER`; `IN_PROGRESS ↔ WAITING_FOR_CUSTOMER`; `IN_PROGRESS / WAITING_FOR_CUSTOMER → RESOLVED`; `RESOLVED → CLOSED`; `RESOLVED → active` only through an approved reopening. Automatic transitions: first support reply on an `ASSIGNED` ticket → `IN_PROGRESS`; requester reply on `WAITING_FOR_CUSTOMER` → `IN_PROGRESS`. A ticket with a pending reopening request cannot be closed until the request is decided. | BR-009, BR-010, BR-049..BR-053, CS-02 ticket-behavior diagram (which includes `WAITING_FOR_CUSTOMER → RESOLVED`). |
| DEC-CS03-08 | **Agent authority:** an agent has full operational authority on tickets assigned to them; on *unassigned* tickets an agent may triage (priority incl. Critical, category, internal note, escalation, self-assignment) but must take the ticket before replying or changing status; on another agent's ticket an agent can only view. Managers and administrators act on every ticket; administrators are not assignable. | BR-056..BR-061, BR-067..BR-071. The triage authority on unassigned tickets is an interpretation of "otherwise authorized to handle": **owner confirmation needed.** |
| DEC-CS03-09 | **Requester priority:** requesters choose Low/Medium/High and may tick "urgent"; Critical is rejected (422) and only support can set it. | BR-036, BR-037, AC-014, AC-015, CS-02 wireframes ("no direct Critical control"). |
| DEC-CS03-10 | **Escalation** is a flag on the ticket (not a lifecycle status), audited and notified to managers. | BR-064; the approved status list has no escalated status. |
| DEC-CS03-11 | **Attachments:** type detected from the file content (magic bytes) and required to match the extension; files stored under server-generated keys in a private directory and served only through the authorized download endpoint with `Content-Disposition: attachment` and `nosniff`. Cloudinary (authenticated delivery) can replace the storage adapter later. | DEC-003, BR-040..BR-047, OWASP file-upload guidance. |
| DEC-CS03-12 | **Notifications:** in-app notifications are written after the ticket transaction commits; push goes through Firebase Cloud Messaging with retries (exponential backoff, 5 attempts by default). Without Firebase credentials, push is logged only. | FR-013, BR-020, roadmap Oct. week 4. |
| DEC-CS03-13 | **Ecosystem integration** goes through a read-only `EcosystemGateway` port. A demo adapter provides consistent sample data until the core services expose the proposed HTTP contract. | FR-011, roadmap Oct. week 3. The core services do not exist in the repository yet. |
| DEC-CS03-14 | **Requester visibility:** requesters see status, priority, category, their linked order/delivery reference and the first name of the handling agent; they never see SLA data, payment/seller/refund internals, internal notes or internal history details. | BR-016, BR-072, CS-02 screen inventory (A4 excludes support-only content). |
| DEC-CS03-15 | **Categories** remain the closed CS-01 list: administrators can rename, describe or deactivate (except "Autre") but not add categories. | BR-005, BR-006. The mockup's "Ajouter une catégorie" needs a change request. |
| DEC-CS03-16 | **Basic report** for managers/administrators: created/resolved counts, average first-response and resolution time in business hours, SLA met %, distribution by category and per day. | Functional design §18 and IA "Rapports". Kept basic to respect the CS-01 exclusion of advanced analytics: **owner confirmation needed.** |
| DEC-CS03-17 | **Web session:** the web app stores the access token in an httpOnly, SameSite=Lax cookie and calls the API through a same-origin proxy that also rejects cross-origin state-changing requests. | OWASP session management; keeps tokens out of JavaScript. |
| DEC-CS03-18 | **Errors** follow RFC 9457 (`application/problem+json`) with a stable `code` and, when relevant, the business `rule` (e.g. `BR-036`). | REFERENCES.md (RFC 9457). |

| DEC-CS11-01 | **Hexagonal modules and transactional outbox.** Every backend module (`ticket`, `sla`, `notification`, `attachment`, `context`, `identity`, `report`) is split into `domain` (framework-free Java), `application` (use cases + `port` interfaces, only `@Service`/`@Transactional` from Spring) and `adapter.in.*` / `adapter.out.*` (web, events, schedulers, JPA, HTTP clients, storage, antivirus, push) wired by one `<Module>Config`; `shared` is the kernel (Actor, Role, SupportException, events) and `platform` the technical base.
