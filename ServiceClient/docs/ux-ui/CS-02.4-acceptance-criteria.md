# CS-02.4 Acceptance Criteria — Screen Behavior

- AC-SB-001 Global states are defined.
- AC-SB-002 Lifecycle matches CS-01.
- AC-SB-003 Create Ticket produces `NEW`.
- AC-SB-004 Requester cannot directly set `CRITICAL`.
- AC-SB-005 Invalid attachments receive actionable rejection.
- AC-SB-006 Message sending prevents duplicates.
- AC-SB-007 Internal notes are not customer-visible.
- AC-SB-008 Valid transitions are enforced.
- AC-SB-009 Invalid transitions are denied.
- AC-SB-010 Agent can self-assign unassigned tickets when authorized.
- AC-SB-011 Normal cross-agent reassignment is unavailable to Agent.
- AC-SB-012 Manager/Admin can perform permitted reassignment.
- AC-SB-013 SLA exposes first-response and resolution state.
- AC-SB-014 Reopening follows approved support decision flow.
- AC-SB-015 CLOSED cannot be requester-reopened.
- AC-SB-016 Notification failure does not corrupt core state.
- AC-SB-017 Authorization errors do not leak protected data.
- AC-SB-018 Recoverable failures provide retry/recovery.
- AC-SB-019 Attachment limits match CS-01.
- AC-SB-020 Context is shown only when authorized.
- AC-SB-021 Important/final actions are deliberate.
- AC-SB-022 Action availability depends on user, role, state, assignment, and authorization.
