# CS-02.6 Acceptance Criteria — Design System & Prototype

- AC-DS-001 Shared Maplenou UI language is defined.
- AC-DS-002 Semantic tokens are defined.
- AC-DS-003 Status vocabulary matches CS-01.
- AC-DS-004 Priority vocabulary matches CS-01.
- AC-DS-005 Critical prominence does not imply universal edit permission.
- AC-DS-006 Button hierarchy is defined.
- AC-DS-007 Form structure includes labels and validation.
- AC-DS-008 Attachment component represents states/errors.
- AC-DS-009 Visible messages and internal notes are distinct.
- AC-DS-010 SLA component represents approved states.
- AC-DS-011 Notifications have consistent structure.
- AC-DS-012 Important actions can use confirmation.
- AC-DS-013 Loading avoids duplicate submissions.
- AC-DS-014 Empty states distinguish causes.
- AC-DS-015 Errors are actionable.
- AC-DS-016 Responsive behavior is defined.
- AC-DS-017 WCAG 2.2 is the accessibility baseline.
- AC-DS-018 Component inventory covers principal patterns.
- AC-DS-019 Prototype scope covers representative requester/support flows.
- AC-DS-020 Prototype excludes real backend/storage/notifications/authentication and deferred AI/predictive functionality.
